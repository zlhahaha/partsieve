## WPS保存与显示的已知限制

- 三份原始清理输出均无`word/styles.xml`，独立OpenXML检查通过。WPS保存时新增三个默认style，将`uiPriority`放在`qFormat`或`semiHidden`之后；Open XML SDK 3.3.0 / Office2007每份报告三处`Sch_UnexpectedElementContentExpectingComplex`。在独立诊断副本中只调整这三个元素的顺序，其他内部文件保持原字节，三份格式检查均通过。这些副本是另行修改的客户端归档副本，不能冒充原始清理输出或沿用旧回执。
- 预先加入合法默认样式的对照文件，交给同一WPS保留兼容格式另存后仍出现同类三处错误；不能宣称给输入补样式就已解决客户端写出问题。原始输出的保留契约不授权自动增加样式或修改正常布局。
- 三份WPS保存副本的正文（除有意编辑标记）、表格文字、节数、页眉页脚文字及唯一图片数据相同；但WPS把正文、页眉和页脚的关系型超链接改写为`HYPERLINK`字段，三个URL文本保留。字段仍属于当前输入配置的拒绝范围，不能保证保存副本可再次由PartSieve处理；这也不是PartSieve的字节保留证明。
- 32对象长段落在本机WPS的100%缩放下部分字形显示裁切，未修改原始文件在120%时显示正常，回到100%可复现。单独加入显式自动行距未在100%下消除现象；这提示缩放相关的客户端显示问题，不能推断数据丢失或确定所有设备的底层原因。可先用120%查看，完整视觉保真仍未验证。
- 客户端保存副本应另存后独立校验；原件、PartSieve清理输出、客户端保存副本和后续修正副本需分别留存。原始失败证据未被修正副本覆盖，校验标准没有放宽。本轮原始证据与截图仅保存在本地。
